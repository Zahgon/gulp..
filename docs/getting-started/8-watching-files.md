# Watching Files

The `Watch()` function watches globs and runs a task whenever a matching file
changes. It is what turns a build into a development loop.

```go
package main

import (
	"context"
	"log"

	gulp "github.com/gulpjs/gulp-go"
)

func clean(ctx context.Context) error  { return nil }
func styles(ctx context.Context) error { return nil }

func main() {
	gulp.Task("clean", clean)
	gulp.Task("styles", styles)

	gulp.Task("watch", func(ctx context.Context) error {
		w, err := gulp.Watch(
			[]string{"src/**/*.scss"},
			gulp.WatchOptions{},
			gulp.Default.Series(gulp.Names("clean", "styles")...).Fn,
		)
		if err != nil {
			return err
		}
		defer w.Close()

		<-ctx.Done()
		return nil
	})

	gulp.Main()
}
```

Three details of that example matter.

The watcher runs until you stop it, so the task blocks on `<-ctx.Done()`. The
context is cancelled when you press Ctrl-C, which is what lets `defer w.Close()`
shut the watcher down cleanly.

`Close()` must be called. Unlike JavaScript, where an unreferenced chokidar
instance is eventually collected, a Go watcher owns goroutines and operating
system handles that live until you release them.

The task is `Series(...).Fn` rather than a bare name. `Watch` takes a
`TaskFunc`, so a name has to be turned into one first — see
[Creating Tasks][creating-tasks].

> In JavaScript, passing a task *name* to `gulp.watch` throws
> `watching src/**/*.scss: watch task has to be a function (optionally
> generated by using gulp.parallel or gulp.series)`. In Go the parameter is
> typed, so the same mistake is a compile error and the message is unreachable.

## Globs

Watch globs follow the same rules as [`Src()` globs][globs], including negation:

```go
w, err := gulp.Watch(
	[]string{"src/**/*.scss", "!src/vendor/**"},
	gulp.WatchOptions{},
	build,
)
```

Globs are resolved against `Cwd`, which defaults to the process working
directory:

```go
gulp.WatchOptions{Cwd: "src"}
```

Paths reported to listeners are relative to that same `Cwd`, as chokidar does.

## Options

| Option                   | Type                | Default              | Purpose |
| :----------------------- | :------------------ | :------------------- | :------ |
| `Cwd`                    | `string`            | process cwd          | Base for globs and reported paths. |
| `IgnoreInitial`          | `*bool`             | `true`               | Skip the burst of events for files that already exist. |
| `Delay`                  | `*time.Duration`    | `200ms`              | Debounce window before the task runs. |
| `Queue`                  | `*bool`             | `true`               | Queue at most one run while a run is in progress. |
| `Events`                 | `[]EventKind`       | add, change, unlink  | Which events trigger the task. |
| `Ignored`                | `[]string`          | none                 | Globs never reported, pruned before descending. |
| `FollowSymlinks`         | `*bool`             | `true`               | Descend through symlinked directories. |
| `DisableGlobbing`        | `bool`              | `false`              | Treat every path as a literal. |
| `UsePolling`             | `bool`              | `false`              | Use the stat-polling backend. |
| `Interval`               | `*time.Duration`    | `100ms`              | Poll interval when polling. |
| `Depth`                  | `*int`              | unlimited            | How far below each root to descend. |
| `AwaitWriteFinish`       | `*AwaitWriteFinish` | off                  | Wait for a file to stop growing before reporting it. |
| `IgnorePermissionErrors` | `bool`              | `false`              | Skip directories that cannot be read. |
| `Atomic`                 | `*time.Duration`    | `100ms`              | Collapse an unlink immediately followed by an add into a change. |

Fields whose default is not the Go zero value are pointers, so that "unset" and
"explicitly false" are distinguishable. Use `gulp.Ptr` to set them:

```go
gulp.WatchOptions{
	IgnoreInitial: gulp.Ptr(false),
	Delay:         gulp.Ptr(500 * time.Millisecond),
	Queue:         gulp.Ptr(false),
}
```

> `IgnoreInitial` defaults to `true` and `Delay` to `200ms`. Both differ from
> chokidar's own defaults, and both match gulp.

## The delay and the queue

Editors write files in bursts — a save can produce several events in a few
milliseconds, and a `git checkout` can produce thousands. Two settings keep that
from turning into a stampede of builds.

`Delay` debounces. Every event restarts the timer, so the task runs once the
filesystem has been quiet for `Delay`.

`Queue` bounds concurrency. While a run is in progress, further changes set a
single flag rather than starting more runs; when the run finishes, the task runs
exactly once more if the flag is set. Five saves during a slow build produce two
runs in total, not six. Setting `Queue` to false discards changes that arrive
during a run.

## Events

By default a task runs for added, changed and unlinked files. Directory events
are ignored:

```go
gulp.WatchOptions{
	Events: []gulp.WatchEventKind{
		gulp.WatchEventAdd,
		gulp.WatchEventChange,
		gulp.WatchEventUnlink,
		gulp.WatchEventAddDir,
		gulp.WatchEventUnlinkDir,
	},
}
```

`watch.EventAll` in the slice expands to all five.

To react to a specific event rather than run a task, register a listener:

```go
w, err := gulp.Watch([]string{"src/**/*.scss"}, gulp.WatchOptions{}, nil)
if err != nil {
	return err
}
defer w.Close()

w.On(gulp.WatchEventUnlink, func(path string) {
	log.Printf("deleted: %s", path)
})
w.OnError(func(err error) {
	log.Printf("watch error: %v", err)
})

<-ctx.Done()
```

Passing `nil` as the task is legal, and is how you build a watcher that only
drives listeners.

`Ready()` closes once the initial scan is done, which is what a test should wait
for before touching files:

```go
<-w.Ready()
```

## Backends

Two implementations sit behind the same interface.

The default uses the operating system's notification API through
[`fsnotify`][fsnotify], and maintains recursion itself: every directory under a
watch root is registered, and directories created later are registered as they
appear.

`UsePolling: true` switches to stat-based polling. It is slower and busier, but
it works on network filesystems and inside containers where notifications are
not delivered:

```go
gulp.WatchOptions{
	UsePolling: true,
	Interval:   gulp.Ptr(500 * time.Millisecond),
}
```

Both backends produce identical events; the watch test suite runs every case
against both.

## Atomic saves

Many editors save by writing a temporary file and renaming it over the original,
which the filesystem reports as an unlink followed immediately by an add. The
`Atomic` window collapses that pair into a single change event, so a save looks
like a save rather than a delete-and-recreate.

## Non-ASCII paths

On macOS, APFS stores filenames in Unicode NFD while a glob written in a Go
source file is almost always NFC, so `フォルダ/*` would silently match nothing.
Both the pattern and every event path are normalised to NFC before matching, so
non-ASCII globs work the way you would expect.

## Incremental rebuilds

Watching pairs naturally with `LastRun`, which reports when a task last
*succeeded*:

```go
func styles(ctx context.Context) error {
	opts := gulp.SrcOptions{}
	if since, ok, _ := gulp.LastRun(gulp.Name("styles"), 0); ok {
		opts.Since = gulp.Value(since)
	}
	return gulp.Src([]string{"src/**/*.scss"}, opts).
		Pipe(gulp.Dest("dist")).
		Run(ctx)
}
```

The first run compiles everything; later runs only read files modified since the
previous success. Because a failed run is not recorded, a build that errors is
retried in full rather than skipping the files it never got to.

## Options with no effect

`Persistent`, `AlwaysStat` and `BinaryInterval` are accepted for source
compatibility but do nothing. A Go watcher's lifetime is controlled by
`Close()` rather than by an event loop reference count, every event already
carries a stat, and the notification backend does not distinguish binary files.
